# Research: pi-desktop GitHub repositories

## Summary
The three projects all wrap Pi locally, but use different host architectures: gustavonline and StarkInternationalAI are Tauri/Lit apps that spawn `pi --mode rpc` directly from Rust, while tanRdev is an Electron/React app with a richer split between renderer, main process, utility agent-host processes, sockets, and optional terminal backends. The most reusable ideas are: typed JSONL/RPC over stdio, per-session/process isolation, generation or ownership guards, explicit CLI discovery/path repair for GUI-launched apps, and clear separation between agent runtime, terminal runtime, and desktop UI.

## Findings
1. **gustavonline/pi-desktop is a minimal Tauri shell around `pi --mode rpc`.** The README and architecture doc define a three-layer model: desktop host, Pi CLI runtime, and packages/extensions; the app owns panes/tabs/files/notifications while Pi owns model execution, session state, tools, and package behavior. This is a clean boundary for avoiding workflow hardcoding in the desktop app. [README](https://github.com/gustavonline/pi-desktop/blob/main/README.md), [Architecture](https://github.com/gustavonline/pi-desktop/blob/main/docs/ARCHITECTURE.md)

2. **gustavonline runs Pi via Rust-managed child processes, one per RPC instance, over stdin/stdout JSON lines.** `RpcState` stores a `HashMap<String, RpcProcessHandle>` with generation, child process, and stdin writer; `rpc_start` kills/replaces an existing instance, spawns `pi --mode rpc`, reads stdout/stderr on threads, and emits Tauri events `rpc-event`, `rpc-stderr`, and `rpc-closed`. `rpc_send` and `rpc_ui_response` write one JSON line to stdin. [src-tauri/src/lib.rs](https://github.com/gustavonline/pi-desktop/blob/main/src-tauri/src/lib.rs)

3. **gustavonline has strong CLI discovery and GUI PATH repair.** Discovery order is manual `pi_path`, dev `cli_path`, env overrides (`PI_DESKTOP_PI_PATH`, `PI_CLI_PATH`), packaged sidecar, PATH, then common npm locations. When spawning script-based Pi binaries, it prepends the binary directory to PATH to handle macOS/GUI launches where shell profiles are not sourced. [src-tauri/src/lib.rs](https://github.com/gustavonline/pi-desktop/blob/main/src-tauri/src/lib.rs)

4. **gustavonline’s terminal is xterm UI plus Tauri shell commands, not a full native PTY manager.** `TerminalPanel` renders xterm, resolves allowed shell profiles, runs shell commands via `@tauri-apps/plugin-shell`, queues commands while one is running, and forwards limited interactive keys to the spawned child. It has a special bridge for interactive `pi`/login using `script` on Unix, but this remains more command-runner-like than tanRdev’s node-pty terminal. [terminal-panel.ts](https://github.com/gustavonline/pi-desktop/blob/main/src/components/terminal-panel.ts)

5. **StarkInternationalAI/pi-desktop is also Tauri/Lit but more project/session-persistence oriented.** Its README describes project configs, JSONL sessions, SQLite/FTS session indexing, session outline, slash commands, extension UI bridging, and a permissions extension. Architecture shows frontend `RpcAgentAdapter` talking through Tauri IPC to Rust `ProcessMgr`, with child `pi --mode rpc` processes “one per session.” [README](https://github.com/StarkInternationalAI/pi-desktop/blob/main/README.md)

6. **StarkInternationalAI spawns one Pi process per session with project-specific flags and extensions.** `ProcessManager::spawn` builds `pi --mode rpc --session <file>`, adds provider/model defaults, `--append-system-prompt`, `--extension`, `--models`, `--skill`, and injects a temp permission config via `PI_DESKTOP_PERMISSIONS_CONFIG`. It forwards credential/PATH/HOME env vars explicitly and records a shell-escaped launch command for diagnostics. [process_manager.rs](https://github.com/StarkInternationalAI/pi-desktop/blob/main/src-tauri/src/process_manager.rs), [agent.rs](https://github.com/StarkInternationalAI/pi-desktop/blob/main/src-tauri/src/commands/agent.rs)

7. **StarkInternationalAI IPC is simple and direct.** Frontend calls Tauri commands `agent_spawn`, `agent_send`, `agent_kill`, and `agent_get_launch_command`; Rust writes serialized command JSON to a Tokio mpsc stdin writer, parses stdout lines as JSON, emits `agent-event`, and skips non-JSON stdout. On `message_end`, it also indexes preview text into SQLite for the session outline. [process_manager.rs](https://github.com/StarkInternationalAI/pi-desktop/blob/main/src-tauri/src/process_manager.rs), [rpc-agent-adapter.ts](https://github.com/StarkInternationalAI/pi-desktop/blob/main/src/rpc-agent-adapter.ts)

8. **StarkInternationalAI shutdown is graceful-first, then SIGTERM.** `kill` removes the process, sends `{"type":"abort"}`, drops stdin after a short delay, then sends Unix `SIGTERM` if a PID is still present and aborts background tasks. Reusable: expose launch-command diagnostics and try protocol-level abort before OS termination. [process_manager.rs](https://github.com/StarkInternationalAI/pi-desktop/blob/main/src-tauri/src/process_manager.rs)

9. **StarkInternationalAI does not appear to implement a general embedded terminal.** The codebase focuses on agent chat/session UI; Tauri capabilities include `shell` and `fs`, but there is no terminal manager comparable to gustavonline’s `TerminalPanel` or tanRdev’s `TerminalManager`. [default.json](https://github.com/StarkInternationalAI/pi-desktop/blob/main/src-tauri/capabilities/default.json), [README](https://github.com/StarkInternationalAI/pi-desktop/blob/main/README.md)

10. **tanRdev/pi-desktop is the most elaborate desktop harness: Electron main process, secure preload, React renderer, shared packages, and agent-host abstraction.** README describes runtime modes `mock`, `CLI`, and `Pi SDK`, repository/worktree management, integrated terminals, packages, and a hardened preload bridge where the renderer has no direct Node access. [README](https://github.com/tanRdev/pi-desktop/blob/main/README.md), [preload api](https://github.com/tanRdev/pi-desktop/blob/main/apps/desktop/src/preload/api.ts)

11. **tanRdev separates per-thread agent runtimes into child Electron-as-Node processes and Unix sockets.** `createThreadRuntimeLaunchDetails` builds a command using `ELECTRON_RUN_AS_NODE=1` plus env vars for socket path, mode, cwd, and per-thread agent dir; `LocalThreadRuntimeManager` starts/stops these runtime processes and reuses them when command/worktree signatures match. The socket transport/server exchange newline-delimited JSON envelopes and broadcast events to connected clients. [thread-runtime-launch.ts](https://github.com/tanRdev/pi-desktop/blob/main/apps/desktop/src/main/thread-runtime-launch.ts), [local-thread-runtime-manager.ts](https://github.com/tanRdev/pi-desktop/blob/main/apps/desktop/src/main/local-thread-runtime-manager.ts), [agent-host-socket-transport.ts](https://github.com/tanRdev/pi-desktop/blob/main/apps/desktop/src/main/agent-host-socket-transport.ts), [socket-bridge.ts](https://github.com/tanRdev/pi-desktop/blob/main/packages/agent-host/src/session-server/socket-bridge.ts)

12. **tanRdev’s CLI runtime is an abstraction over `pi --mode rpc --continue`.** `PiCliRpcAgentRuntime` bootstraps a child process, attaches lifecycle handlers, sends serialized RPC commands with pending request tracking, refreshes snapshots, and applies incoming RPC lines to an `AgentSnapshot`. Spawn request uses `PI_CLI_PATH` when present, otherwise `pi`, and sets `PI_CODING_AGENT_DIR` to the isolated runtime agent dir. [pi-cli-rpc-agent-runtime.ts](https://github.com/tanRdev/pi-desktop/blob/main/packages/agent-host/src/pi/pi-cli-rpc-agent-runtime.ts), [pi-cli-rpc-spawn.ts](https://github.com/tanRdev/pi-desktop/blob/main/packages/agent-host/src/pi/pi-cli-rpc-spawn.ts)

13. **tanRdev has the most reusable terminal embedding approach.** `TerminalManager` loads `node-pty` if available, falls back to `child_process.spawn`, supports `shell` and `pi` backends, emits session output to the renderer, enforces a 16MB cumulative scrollback cap, tracks owning WebContents, supports resize/write/destroy, and uses escalation cleanup for non-PTY child processes. The `pi` terminal backend runs Pi with `--continue` and sets `PI_CODING_AGENT_DIR` plus enhanced PATH. [terminal-manager.ts](https://github.com/tanRdev/pi-desktop/blob/main/apps/desktop/src/main/terminal-manager.ts)

14. **tanRdev’s terminal IPC adds practical safety controls.** `registerTerminalHandlers` validates payloads, requires terminal cwd to resolve inside allowed repository/worktree roots, checks that writes/resizes/destroys come from the owning renderer, and caps write payloads at 64KB. These are directly reusable controls for any desktop terminal integration. [register-terminal-handlers.ts](https://github.com/tanRdev/pi-desktop/blob/main/apps/desktop/src/main/ipc/register-terminal-handlers.ts)

15. **Limitations differ by repo.** gustavonline’s terminal is lighter and less PTY-native; StarkInternationalAI lacks a full terminal and is tightly shaped around project/session persistence; tanRdev is alpha, macOS-oriented, more complex, and depends on native Electron/node-pty packaging. All three still rely on local `pi` CLI availability or discovery, environment propagation, and careful process cleanup. [gustavonline README](https://github.com/gustavonline/pi-desktop/blob/main/README.md), [StarkInternationalAI README](https://github.com/StarkInternationalAI/pi-desktop/blob/main/README.md), [tanRdev README](https://github.com/tanRdev/pi-desktop/blob/main/README.md)

## Gaps
- I did not run the apps, so observations are source-code/static only; behavior such as terminal resize fidelity, PTY quirks, and RPC compatibility should be verified with runtime tests.
- I did not audit every renderer component; this brief focuses on process/terminal/IPC paths.
- Next steps: prototype terminal with tanRdev’s node-pty ownership/cwd/write caps, combine with gustavonline’s CLI discovery/path repair, and use StarkInternationalAI’s launch-command diagnostics plus protocol-level abort-before-kill pattern.
