## Review
- Correct: The official docs cover the high-level native-subagent model. `pi-documentation/official-documentation/user-guide/native-subagents.md:3-17` states that Pi Manager owns child RPC processes, run records, transcripts, artifacts, supervisor requests, worktrees, and graph metadata, matching the source overview in `pi-documentation/native-subagents.md:1-15`.
- Correct: The official docs include the bundled starter agents and expected-outcome safety model. `pi-documentation/official-documentation/user-guide/native-subagents.md:19-54` covers `scout`, `planner`, `worker`, `reviewer`, artifact paths, expected outcomes, and advisory `output` frontmatter, which matches `pi-documentation/native-subagents.md:19-55`.
- Correct: The official docs include read-first-file safety and supervisor routing at a summary level. `pi-documentation/official-documentation/user-guide/native-subagents.md:56-68` covers project-relative read-first hints and `contact_supervisor` request types, and `pi-documentation/official-documentation/reference/native-subagent-bridge.md:5-35` covers parent bridge tools, child bridge tools, fork fallback, and extension isolation, aligning with `pi-documentation/native-subagents.md:57-115`.
- Correct: The official docs capture the core slash-entry distinction. `pi-documentation/official-documentation/user-guide/prompts-and-commands.md:1-43` distinguishes built-in commands, extension commands, prompt templates, and skill commands, matching the source model in `pi-documentation/pi-commands-and-prompt-templates.md:19-29` and `pi-documentation/pi-commands-and-prompt-templates.md:251-281`.
- Correct: The official docs capture major resource-management concepts: library vs active resources (`pi-documentation/official-documentation/concepts/resource-scopes-and-resolution.md:17-22`), agent skill references (`pi-documentation/official-documentation/user-guide/agents.md:38-45`), chain managed locations and legacy-chain caveat (`pi-documentation/official-documentation/user-guide/chains.md:5-23`), and skill library activation rules (`pi-documentation/official-documentation/user-guide/skills.md:5-22`). These match the source resource-management details in `pi-documentation/pi-manager-resource-management.md:21-35`, `pi-documentation/pi-manager-resource-management.md:101-117`, and `pi-documentation/pi-manager-resource-management.md:138-167`.
- Blocker: `pi-documentation/official-documentation/concepts/resource-scopes-and-resolution.md:23-34` presents the “Agent precedence” list as builtin, global custom, project custom, then overrides. The source says the effective precedence is project custom, then global custom, then builtin, with builtin overrides patching only when the builtin is still the winner (`pi-documentation/pi-manager-resource-management.md:258-277`). The current official wording can be read as the opposite winner order and should be corrected or rewritten as “the effective view accounts for...” plus an explicit winner order.
- Blocker: The official documentation does not appear to include or link the Pi core system-prompt/context-file reference. The source identifies this as a main source of truth for Pi core prompt assembly and normal-session behavior (`pi-documentation/pi-core-system-reference-and-subagents.md:9-19`) and documents important rules for `SYSTEM.md`, `APPEND_SYSTEM.md`, `AGENTS.md`/`CLAUDE.md`, `--system-prompt`, `--append-system-prompt`, and discovery order (`pi-documentation/pi-core-system-reference-and-subagents.md:149-167`, `pi-documentation/pi-core-system-reference-and-subagents.md:196-224`, `pi-documentation/pi-core-system-reference-and-subagents.md:226-253`). A grep of `pi-documentation/official-documentation/**/*.md` found no references to `SYSTEM.md`, `APPEND_SYSTEM`, `--system-prompt`, `--no-context-files`, `--no-skills`, `AGENTS.md`, or `CLAUDE.md` beyond the docs folder’s own `AGENTS.md`. This is important because the official docs otherwise explain resources but omit how Pi actually assembles runtime instructions.
- Note: `pi-documentation/official-documentation/user-guide/native-subagents.md` omits several source details that are important enough to include directly or link from the bridge/safety references: the system-prompt construction steps (`pi-documentation/native-subagents.md:72-90`), activity-sidebar plan/feed behavior (`pi-documentation/native-subagents.md:92-100`), app cleanup/retention for orphaned run directories (`pi-documentation/native-subagents.md:127-135`), and session-level enablement controls (`pi-documentation/native-subagents.md:137-139`). Some pieces are partially covered in `reference/native-subagent-bridge.md`, but the user guide has no link from those omitted sections.
- Note: `pi-documentation/official-documentation/user-guide/prompts-and-commands.md:17-26` lists CLI prompt-template paths but omits the source’s explicit disable flag `--no-prompt-templates` (`pi-documentation/pi-commands-and-prompt-templates.md:135-139`, `pi-documentation/pi-core-system-reference-and-subagents.md:372-375`) and omits the Pi Manager caveat that the app does not infer CLI-only runtime choices like `--prompt-template` and `--no-prompt-templates` (`pi-documentation/pi-commands-and-prompt-templates.md:282-299`). That caveat matters because the official page mixes Pi runtime locations with Pi Manager’s scanned prompt resources.
- Note: `pi-documentation/official-documentation/user-guide/prompts-and-commands.md:32-39` shows `argument-hint: [focus]`. The source describes `argument-hint` as a human hint and demonstrates it as a string (`pi-documentation/pi-commands-and-prompt-templates.md:175-180`, `pi-documentation/pi-commands-and-prompt-templates.md:218-229`). If Pi expects a string, the official example should use a scalar such as `argument-hint: "<focus>"` to avoid teaching an array-shaped value.
- Note: `pi-documentation/official-documentation/user-guide/skills.md:24-29` summarizes discovery rules but omits settings-based and CLI-based skill discovery, including the important source rule that repeatable `--skill <path>` is honored even when `--no-skills` is used (`pi-documentation/pi-skills-discovery.md:86-127`). `pi-documentation/official-documentation/reference/file-locations.md:48` mentions package/settings skills, but no official page found covers CLI skill injection or this `--no-skills` exception.
- Note: `pi-documentation/official-documentation/reference/file-locations.md:43-48` lists legacy global/project skill paths as `~/.agents/skills/<skill>/SKILL.md` and `PROJECT/.agents/skills/<skill>/SKILL.md`, but the source says legacy `.agents/skills/` discovery is recursive in cwd and ancestors, ignores root `*.md`, and stops at `SKILL.md` roots (`pi-documentation/pi-skills-discovery.md:33-38`, `pi-documentation/pi-skills-discovery.md:56-65`, `pi-documentation/pi-skills-discovery.md:136-147`). The simplified table is not wrong for the common case, but it should link to `user-guide/skills.md` or explicitly say recursive `SKILL.md` directories are supported so readers do not infer only one fixed path shape.
